# 500m 격자 전환 가이드

1km(786셀) → 500m(약 3,100셀) 전환 절차와 재검증 점검 목록.
코드는 전부 파라미터화돼 있어 **데이터가 도착하면 재실행만으로** 500m 산출이 나온다.
다만 임계값·검증 수치는 1km 분포에서 튜닝된 것이라 아래 점검 목록을 반드시 통과시켜야 한다.

## 0. 왜 500m 인가 (9등분이 아니라)

- SGIS 표준 격자는 100m/250m/500m/1km — **1km 의 9등분(333m)은 표준에 없다.**
- 1km 인구를 임의 분할해 채우면 지어낸 정밀도가 된다(목업 금지 방침 위반).
  500m 는 SGIS 가 실측 통계를 제공하므로 실데이터 요건을 지킨다.

## 1. 데이터 신청·배치

1. [SGIS 통계지리정보서비스](https://sgis.kostat.go.kr) → 자료 신청 →
   **500m 격자 경계 + 격자 통계(인구·가구·주택·종사자, 2024년)**, 대상 지역: 경기(또는 전국).
   ※ 공공데이터포털 배포판(현재 사용분)은 `_1K` 만 있다.
2. 받은 파일을 기존 1km 와 같은 폴더 구조에 **접미사만 바꿔** 배치한다
   (파일명이 다르면 이 규칙대로 개명한다 — 이것이 파이프라인의 파일 계약):

```
dataset/국가데이터처_SGIS 격자 통계 및 경계/
├── 1. 통계/1. 2024년 격자 통계(인구)/2024년_인구_다바_500M.csv   (블록 6종 × 통계 4종)
└── 2. 경계/grid_다바/grid_다바_500M.shp  (+ .dbf .shx, 블록 6종)
```

3. shp 속성에 `GRID_CD` 필드가 있는지, 통계 CSV 가 (격자코드·항목코드·값) long format
   cp949 인지 확인. 다르면 `02_grid.py` 의 `read_stat`/필드명을 맞춘다.

## 2. 실행 순서

```bash
python analysis/02_grid.py --size 500   # 격자 재생성 + grid_spec.json 갱신
python analysis/03_join.py              # 무변경 재실행 (전부 미터 기준)
python analysis/04_model.py             # ⚠️ 아래 3장 점검 목록 확인하며
python analysis/07_validate.py          # ⚠️ R²·정성대조 재확보 필수
python analysis/05_simulate.py          # 기준선 일치 assert 통과 확인
python analysis/05_load.py              # server/static JSON 재생성
python main.py                          # 서버 재기동
node ../hwaseong-dashboard/tools/e2e-live.js   # 격자 무관 E2E (전 항목 통과해야)
```

프론트엔드는 로직 수정이 없다 — 셀 크기·개수·범례·줌 한도·부제가 전부
`GET /meta` 의 `meta.grid` 에서 파생된다. 단 **배치 마커 크기(r=8.5px)·겹침
오프셋·선택링 패딩은 고정값**이라 500m 셀(≈8.6px)에서는 마커가 이웃 셀을 덮는다 —
실화면을 보고 `map.js` 의 해당 상수를 줄일 것 (시각 판단 필요라 자동화하지 않음).

## 3. 재튜닝 점검 목록 (04_model)

전부 1km 분포에서 튜닝된 값이다. 500m 재실행 로그·산출을 보며 확인한다.

| 항목 | 1km 근거 | 점검 방법 |
|---|---|---|
| 사분면 컷 `QUAD` (need_mi 0.75 등) | 동탄 침투 4곳 실측으로 상향 | need/drt 비중이 1km 와 크게 다르면 z-분포 히스토그램 대조 후 조정 |
| MI 감쇠 `dRef`(P55)·`DAMP_EXP` 0.65 | 빈 땅 183→0곳 | **빈 땅(인구<50)이 need 색을 받는 셀 = 0** 재확인. dRef 경고 로그 확인 |
| drt 게이트 `fRef`(P30) | — | fRef=0 경고가 뜨면 분위를 인구>0 셀 기준으로 재산정 |
| `COV_THRESHOLD_M` 600 | 중심~정류장 중앙값 392m | 500m 중심거리 중앙값 재측정(≈절반으로 압축됨) 후 유지/조정 판단 |
| action 컷 `cov<0.42` | 348m 등가 | 셀 중심 간격이 절반이라 NEW_STOP 비중 변화 확인 |
| need 비중 assert 2~25% | 1km 4.8% | 밴드 이탈 시 빈 셀 증가가 원인인지 확인 후 분모를 인구>0 셀로 변경 검토 |
| `MI_CLAMP` 2.6 | zD 상한 2.67 | 클립되는 셀 비율 확인 |

## 4. 검증 재확보 (07_validate)

- **R² 0.801 은 1km 수치다.** 500m 는 셀당 승차가 ~1/4 이라 Poisson 노이즈가 커져
  셀 단위 R² 가 구조적으로 하락한다. 목표 0.6 미달이 나오면:
  500m 예측을 1km 부모 격자로 합산해 평가하는 방식(집계 후 R²)을 병기하라 —
  "해상도를 높여도 1km 집계 예측력은 유지" 가 올바른 방어 논리다.
- QUALITATIVE 의 순위 표기("출근 1·4위")와 "다사5612" 격자 ID 는 1km 기록 —
  재실행 Top5 와 대조해 재작성.
- **MAUP 방어 소재**: 1km/500m 우선순위 Top10 의 읍면동 구성을 비교한 표를 만들면
  "격자 크기를 바꿔도 결론이 유지된다"는 강력한 방법론 방어가 된다.

## 5. 성능·페이로드 (서버)

- GZip 미들웨어 적용됨 — 시뮬 응답 ~7MB(500m) → 수백 KB.
- 추천 그리디는 equity 캐시·거리마스크 호이스트·800m 최소 이격이 적용됐지만
  후보×셀 수가 ~16배라 **500m 에서 응답 시간 실측 필수**. 느리면
  후보 프리필터(mi 상위 K)나 반경 내 부분 갱신으로 추가 최적화.
- `/simulations` 의 `cellsByPeriod` 가 커지는 게 부담이 되면 요청 시간대만
  내려주는 옵션을 추가하고 프론트 `paintAll`/기간 탭 전환을 함께 수정할 것.
- `maxPlacements` 상한 50, 셀당 `MAX_COUNT` 20 은 1km 감각의 상수 — 필요시 상향.
