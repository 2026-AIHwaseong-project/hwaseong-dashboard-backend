> **DB 반영은 발표 이후로 미룹니다.** `_run_refresh` 는 `DATABASE_URL` 이 있으면 업로드
> 반영 시 `06_load_db.py` 까지 자동으로 돌립니다. 그런데 2026-08-24 운영 서버에서 DB 를

## 0. 먼저 — 업로드와 무관하게 지금 터져 있는 결함 2건

이 문서를 쓰는 과정에서 발견했고, **직접 코드로 확인했습니다.**
업로드 기능을 만들지 않기로 하더라도 이 둘은 고쳐야 합니다.

### 결함 A — 데이터 갱신이 서버를 못 뜨게 만든다

`analysis/04_model.py`는 산출물 **셋**을 씁니다.

```python
240:  res[out_cols].to_csv(D_DIR / "grid_metrics.csv", ...)
241:  res_we[out_cols].to_csv(D_DIR / "grid_metrics_we.csv", ...)   # ← 주말
243:  json.dump(norm_stats, f, ...)
```

그런데 `server/admin.py`의 교체 목록에는 **둘만** 있습니다.

```python
"model": ["dataset_hwaseong/grid_metrics.csv", "dataset_hwaseong/norm_stats.json"],
#                                    grid_metrics_we.csv 누락 ─┘
```

데이터가 실제로 바뀌는 갱신을 한 번 돌리면 라이브가 **새 `norm_stats` + 옛 `grid_metrics_we`**
혼합이 됩니다. 그러면 `analysis/05_simulate.py:190`에서

```python
assert np.abs(BASE_KPI_WE[_p]["mi"] - S0_WE[_p]["mi0"]).max() < 5e-4, f"[we] 기준선 불일치: {_p}"
```

이 걸려 재적재가 죽고, 컨테이너를 재기동하면 lifespan에서 죽습니다.
`restart: unless-stopped`라 **크래시 루프**가 됩니다.

지금 관리자 콘솔에 이미 있는 [모델 재계산] 버튼으로도 도달할 수 있는 경로입니다.
**업로드보다 우선순위가 높습니다.**

### 결함 B — 교체 루프에 되돌리기가 없다

`server/admin.py`의 `for rel in swap: copy2 → os.replace` 루프에는 try/except도 역스왑도 없습니다.
교체 대상이 26개쯤 되는데 중간에 디스크가 차거나 컨테이너가 OOM으로 죽으면
**앞쪽만 새것**이 되어 결함 A와 똑같은 크래시 루프에 빠집니다.
업로드는 이 루프에 19MB 원본 CSV를 추가로 넣으므로 노출 면적을 직접 키웁니다.

## 1. 현재 구조 — 이미 있는 것과 없는 것

```
[없음: 업로드]  →  스테이징 복사  →  03→04→검증→05  →  시뮬 게이트  →  백업  →  원자 교체  →  재적재
                   └────────────────── 이 구간은 이미 완성돼 있다 ──────────────────┘
```

`_run_refresh()`가 이미 하는 일 — 스테이지 디렉터리에서만 파이프라인을 돌리고,
시뮬레이션 기준선 게이트를 통과한 결과만 백업 후 교체하고, 실패하면 라이브를 건드리지 않습니다.
EXDEV(파일시스템 경계) 문제까지 해결돼 있습니다.

**그래서 새로 만들 것은 네 조각뿐입니다.**

1. 업로드 접수 엔드포인트 (검증 후 `var/upload-*/`에 격리 보관)
2. 스테이지에 업로드 파일을 얹는 오버레이 블록 (약 15줄)
3. 교체 목록에 업로드 원본 추가
4. 관리자 카드 안의 UI 한 줄 (새 화면 없음)

## 2. 무엇을 올릴 수 있게 할 것인가

파일마다 파이프라인이 실제로 읽는지를 확인해 판정했습니다.
**"올렸는데 아무것도 안 바뀐다"가 가장 나쁜 실패**이므로, 효과가 없는 파일은 아예 막습니다.

| 파일 | 판정 | 이유 |
|---|---|---|
| `stops_national_hwaseong.csv` | **허용** (주력) | 정류장 대장 3,158행/341KB. 정류장 수가 화면 KPI에 직접 뜨고 좌표가 공급지수까지 흔든다. 크기가 작아 무대에서 안전 |
| `flow_hourly.csv` | **허용** | 유동인구 시간배율. 잠재수요의 시간축 신호라 효과가 확실하고, 열이 30개라 "스키마를 진짜로 검사한다"는 인상을 준다 |

`datasetId`로 **도달할 문법 자체가 없습니다** — `../` 경로 탈출이 원리적으로 불가능합니다.

## 3. 파급 — 기준선을 어떻게 다룰 것인가

이것이 이 기능의 핵심 쟁점입니다.

`04_model.py`는 실행할 때마다 `norm_stats.json`을 **무조건 재계산해 덮어씁니다.**
동결 옵션이 코드에 없습니다. 즉 "기준선 고정"은 선택지가 아니라 신규 개발이고,
고정하면 옛 모수로 새 분포를 재게 되어 5분위 경계가 무너지는 — 조용히 틀리는 — 종류의 문제가 생깁니다.
5일 안에 검증까지 끝낼 수 없습니다.

**그래서 기본값을 예행(드라이런)으로 둡니다.**
예행은 스테이지 안에서만 기준선을 재발행하고 끝나면 스테이지째 지웁니다.
**라이브 `norm_stats.json`은 누가 무슨 파일을 올려도 바뀌지 않습니다.**
발표 슬라이드의 숫자와 화면이 갈라지는 경로 자체가 사라집니다.

### 예행 결과로 무엇을 보여줄 것인가 — 중요

기준선이 재발행되면 z가 다시 중심화되므로 **사각지대 칸 수는 데이터를 크게 흔들어도 거의 안 움직입니다.**
(측정: 승차량을 전부 1.5배 — 도시 전체 수요 +50% — 로 올려도 출근 시간대 30칸 → 29칸으로 오히려 줄었습니다.)

무대에서 20초를 기다린 끝에 "30칸 → 29칸"이 뜨면 이 기능의 존재 이유가 그 자리에서 사라집니다.
따라서 예행 리포트의 핵심 수치를 다음으로 바꿉니다.

- **격자 판정 변경 수** — 3,144개 중 몇 개의 사분면 판정이 바뀌었나
- **원천 지표** — 행 수 전후, 기준일 범위, 파일 지문
- 홀드아웃 R² 전후

#### 실측 (2026-08-23 · 로컬)

| 픽스처 | 판정 변경 | R² | 상위 5개 읍면동 |
|---|---|---|---|
| 정류장 40개 **추가** | **0** / 3,144 | 0.8521 → 0.8386 | 변화 없음 |
| 정류장 395개 **통폐합**(3,158→2,763) | **123** / 3,144 | 0.8521 → 0.8359 | 변화 없음 |

두 가지를 배웠습니다.

**하나 — 정류장을 더하기만 하면 화면이 안 움직입니다.** 노선이 붙지 않은 새 정류장은
공급지수를 거의 올리지 못합니다. 시연 픽스처는 **빼거나 옮기는** 쪽이어야 합니다.

**둘 — 상위 읍면동 명단은 두 경우 모두 그대로였습니다.** 동탄7동·봉담읍의 우선순위가
압도적이라 웬만한 변화로는 순위가 안 바뀝니다. **대사에서 "1위가 바뀐다"고 약속하면 안 됩니다.**
쓸 수 있는 수치는 `판정 변경 N개 / 3,144개`와 `R² 전후` 둘입니다.

## 4. 작업 순서 — 위에서부터

### P0 — 업로드를 만들지 않더라도 오늘 머지 (5.5h)

**1) `grid_metrics_we.csv` 교체 누락 수정** — 1.5h
교체 목록에 한 줄 추가. 그리고 재발 방지를 위해 **일반화한 회귀 테스트**를 넣습니다 —
"각 스크립트가 실제로 쓰는 산출물 집합 ⊆ 교체 목록"을 검사해, 앞으로 어느 스크립트가
출력을 늘려도 같은 사고가 반복되지 않게 합니다.
**위치**: `server/admin.py` `_STEP_OUT` · `tests/test_pipeline.py` 신규 약 20줄

**2) 교체 루프 방어** — 2h
루프 직전 디스크 여유 확인(부족하면 교체 전에 중단 → 라이브 무변경), `.new` 잔재 정리,
루프 전체를 try/except로 감싸 실패 시 이미 바꾼 파일만 백업에서 되돌리기.
그리고 교체 직전에 "스테이지 산출물 집합 ⊇ 라이브 산출물 집합" 확인 —
`05_load.py`가 주말 파일 부재 시 종료코드 0으로 조용히 건너뛰기 때문에,
안 하면 화면이 평일=새것/주말=옛것으로 갈립니다.
**위치**: `server/admin.py` 백업·교체 블록 · 약 35줄

**3) 수신 전 크기 상한** — 1.5h
FastAPI는 본문을 **전부 버퍼링한 뒤에야** 핸들러를 부릅니다. 핸들러 안의 크기 검사는 사후 통보입니다.
진짜 상한은 라우트 진입 전에 있어야 합니다 — `Caddyfile`에 `request_body { max_size 32MB }`
(지금 상한이 전혀 없습니다), `server/main.py`에 Content-Length 미들웨어,
`docker-compose.yml`에 `mem_limit`.
**위치**: `Caddyfile` · `server/main.py` 약 10줄 · `docker-compose.yml`

**4) 킬 스위치 `HW_UPLOAD_ENABLED`** — 0.5h
*(계획 시점에는 기본 OFF 였습니다. 2026-08-24 자로 기본값을 `1` 로 바꿨습니다 — 위 머리말 참조.
스위치 자체는 그대로 남아 있어 셸 변수로 언제든 되돌릴 수 있습니다.)*
업로드 라우트는 환경변수가 켜져 있을 때만 존재하고, 아니면 404입니다.
**업로드 본체보다 먼저 넣습니다** — 일정에서 잘려나가는 건 항상 뒤쪽이라,
뒤에 두면 무방비로 공개된 채 발표를 맞게 됩니다.
**위치**: `server/admin.py` 약 8줄 · `docker-compose.yml` 2줄

### P1 — 업로드 본체 (24h)

**5) 파일 레지스트리 + 스트리밍 검증 헬퍼** — 4h
허용 3종의 헤더를 순서까지 박아 둡니다. 검증은 **반드시 스트리밍** —
19MB 파일을 통째로 파싱하면 메모리가 414MB까지 뜁니다(측정). 행 수만 세고 키 컬럼은 앞 200행만 봅니다.
**위치**: `server/admin.py` `SPECS` 아래 · 약 130줄

**6) `POST /admin/upload` — 접수 + 즉시 검증 리포트** — 3.5h
순서: 킬스위치 → 작업 중이면 409 → 잠금·간격 제한 → 화이트리스트 → 사유 5자 →
디코드 → 시그니처 검사 → 인코딩 정규화 → 스캔 → `var/upload-*/`에 격리 저장 → 리포트 반환.
**이 시점까지 라이브는 손대지 않습니다.**
**위치**: `server/admin.py` · 약 90줄

**7) 갱신 요청 확장 — 기존 경로 100% 보존** — 2.5h
`apply` 기본값을 그대로 분기에 쓰면 **배포된 프론트가 깨집니다.**
현재 `admin.js:287`은 `{steps, reason, actor}`만 보내므로(확인함) 기본값이 먹어
[모델 재계산]이 45초를 돌고 결과를 버리고, [화면 반영]이 무동작이 되며,
**롤백 절차가 의존하는 버튼까지 죽습니다.** 게다가 완료 토스트는 정상으로 뜹니다.
→ `업로드ID가 없으면 종전과 완전히 동일`로 계산합니다.
그리고 업로드가 있으면 단계 목록을 **서버가 강제 치환**합니다(부분 실행으로 게이트를 우회하는 경로 차단).
**위치**: `server/admin.py` · 약 30줄

**8) `_run_refresh` — 오버레이 · 예행 분기 · 결과 산출** — 5h
스테이지 복사 직후 업로드 파일을 얹되, 해시를 재대조하고 **없으면 하드 실패**합니다
(조용히 건너뛰면 "올렸는데 변경 0개"가 뜹니다). 예행이면 교체·재적재를 건너뛰고
스테이지가 지워지기 직전에 비교 결과를 뽑습니다. 예행은 약 23초로 끝납니다.
**위치**: `server/admin.py` · 약 60줄

**9) 상태 응답에 업로드 블록** — 1h
새 GET 엔드포인트를 만들지 않고 기존 상태 응답에 얹습니다(폴링 배선이 공짜).
디스크 여유도 함께 실어 시연 전에 화면에서 확인할 수 있게 합니다.
**위치**: `server/admin.py` · 약 30줄

**10) 프론트** — 5h
지금 `admin.html`에 `disabled`로 박혀 있는 [원천 재수집] 자리표시자를 그대로 교체합니다.
`api.js`는 **표에 한 줄만** 추가하고 통신 계층은 건드리지 않습니다.
**주의**: `admin.js:383`이 확인 버튼을 저장 함수에 영구 바인딩해 두었습니다(확인함).
모드 플래그로 분기하지 않으면 [검증 실행] 클릭에 저장이 함께 발화해
**의도치 않은 파라미터 저장 + [적용] 버튼 영구 사망**이 됩니다.
**위치**: `api.js` 1줄 · `admin.html` 7줄 · `admin.js` 약 110줄 · `admin.css` 말미 12줄 (`app.css` 무수정)

**11) 테스트 8건** — 3h
현재 테스트 전체에 `admin` 문자열이 0회라 관리자 API에는 회귀 그물이 전혀 없습니다.
**가장 중요한 2건은 신규 기능이 아니라 기존 경로 회귀**입니다(업로드ID 없는 갱신이 종전대로 동작하는가).
**위치**: `tests/test_api.py` 신규 구간 · 약 130줄

**12) 이력 배선 + 리허설** — 3.5h
접수·예행·반영·실패를 변경 이력에 남기고, 실제 EC2에서 왕복 1회와 4단 복구를 발표자 두 명이 실습합니다.
예행 소요 시간을 **EC2에서 다시 재서** 대본 분량을 맞춥니다(23초는 워크스테이션 값입니다).

### 절단선

시간이 부족하면 **1~10번까지(25.5h)**를 지키고 11·12를 줄입니다.
단 **12번의 복구 리허설은 줄이지 않습니다** — 무대에서 3분과 30분을 가릅니다.

## 5. 이번에 하지 않을 것

| 안 하는 것 | 이유 |
|---|---|
| **Excel(.xlsx) 직접 파싱** | 시연용 파이썬에 `openpyxl`이 없어 "도커에선 되고 무대에선 죽는" 형태가 된다. 대신 **cp949 자동 변환**을 넣는다 — 한국 사용자가 엑셀에서 CSV로 저장하면 십중팔구 cp949고 그게 파이프라인이 죽는 진짜 함정이다. 5줄로 체감의 90%가 해결된다. xlsx 파일을 올리면 "CSV UTF-8로 저장해 주세요"라고 친절히 안내한다 |
| 스키마 자동 감지 | `routes.csv`와 `routes_plus.csv`의 헤더가 **완전히 동일**해 원리적으로 구분 불가. 우회하려고 파일명을 쓰기 시작하면 경로 탈출 방어가 무너진다. 사용자가 목록에서 고른다 |
| `multipart/form-data` | FastAPI는 라우트 **등록 시점**에 `python-multipart`를 검사해 없으면 기동 실패한다. 로컬 conda에는 우연히 깔려 있어 **배포 직전에만 터진다**. 의존성을 추가하면 도커 레이어 캐시가 깨져 EC2가 무거운 패키지를 전부 다시 받는다. base64 JSON이면 의존성 순증 0 |
| 롤백 API | 예행이 기본이라 되돌릴 대상이 대부분 없고 나머지는 P0-2가 덮는다. 검증 없이 시간에 쫓겨 넣으면 오히려 새 파괴 경로가 된다. 복구 명령을 이력에 문자열로 남기고 리허설로 실습한다 |
| 업로드 진행률 막대 | `fetch`로는 불가능하고 XHR을 쓰면 통신 계층이 두 벌로 갈린다. 진짜 대기는 재계산 구간이고 그건 이미 로그가 실시간으로 보여준다 |
| 드래그앤드롭 | 디자인 규칙이 굵은 점선·큰 이모지를 금지한다. `<label>`+`<input type=file>`이 키보드·스크린리더까지 공짜로 해결한다 |
| 업로드 직후 자동 갱신 | 반드시 "접수 → 리포트 → 사람이 확인 → 실행" 2단 |

## 7. 결정이 필요한 것

| 질문 | 권고 |
|---|---|
| 무대에서 [라이브 반영]을 실제로 누를 것인가 | **누르지 않기.** 누르면 이후 세션 내내 대시보드가 슬라이드와 다른 숫자를 보인다. "기본값이 안전 모드입니다"를 설명으로 쓴다 |
| 19MB 승하차 파일을 목록에 넣을 것인가 | **넣되 무대에서 쓰지 않기.** 목록에 없으면 설득력이 떨어지고, 올리기엔 너무 크다 |
| 예행에서 뒷단 두 단계를 뺄 것인가 | **빼기.** 무대 침묵이 45초 → 23초. 반영 경로는 전체를 다시 도므로 게이트가 사라지지 않는다 |
| 5일간 main을 어떻게 다룰 것인가 | **기능 브랜치에서 작업하고 2회만 머지.** 배포가 테스트 게이트 없이 자동으로 나가므로, 커밋마다 심사위원이 볼 URL이 재기동된다. **발표 당일 아침 배포 금지** |
| 심사위원이 즉석에서 파일을 건네면 | **받는다.** 헤더 검사에서 400으로 떨어지며 진단표가 뜨는데, 그게 오히려 "스키마를 진짜로 검사한다"는 증거가 된다. 실패 화면을 미리 봐 둘 것 |

## 8. 시연 흐름 (30초)

1. **(0~5초)** "화성시 담당자가 매달 받는 정류장 대장을 그대로 올려 보겠습니다." → 파일 선택
2. **(5~12초)** 확인창: "서버가 컬럼 9개를 순서까지 대조했고, 행 수가 3,158에서 늘었습니다.
   엑셀에서 저장한 한글 인코딩은 자동으로 변환했습니다.
   **이 시점까지 실제 데이터는 한 바이트도 바뀌지 않았습니다.**"
3. **(12~15초)** [이 데이터로 검증 실행] → 로그가 실시간으로 흐른다
4. **(15~38초)** 로그가 흐르는 동안: "조인, 수요·공급 모델, 홀드아웃 검증이 차례로 돌고 있습니다.
   전 과정이 임시 디렉터리 안에서만 돌고, **검증을 통과한 것만 실제 데이터가 됩니다.**"

   승인하면 반영되고, 되돌릴 백업 경로가 이력에 남습니다." → 변경 이력 두 줄을 보여준다
