# 보고서 생성 파이프라인 보강 계획

> 대상: `POST /api/v1/reports/draft` · `POST /api/v1/chat`(report 모드) · 프론트 `assets/js/report.js`
> 상태: **1~6단계 구현 완료** — 서버 쪽은 모두 반영했습니다(§4). 보류 2건은 그대로 남았습니다(§5).
> 근거: 서버 실기동 후 보고서 생성·RTF/XLSX 내려받기, `_call_ai` 몽키패치로 규격 위반 응답 주입,
> `report.js` 전문 검토 (2026-08-22 `main` 기준 · 요일축·관리자 콘솔 도입 이후 재확인).

## 1. 현재 구조 — 네 단계 중 세 번째가 비어 있다

```
프롬프트 조립  →  모델 호출  →  [응답 검증]  →  내보내기
  손볼 곳 있음    손볼 곳 있음     없음          양호
```

| 단계 | 지금 | 판정 |
|---|---|---|
| 1. 프롬프트 조립 | 지시문·현황·출력 예시를 user 메시지 하나로 이어붙임 | 손볼 곳 있음 |
| 2. 모델 호출 | 단발 호출, `max_tokens 8192`, 잘림 여부 미확인 | 손볼 곳 있음 |
| 3. 응답 검증 | 섹션 수·heading·표 구조·수치 어느 것도 확인하지 않음 | **없음** |
| 4. 내보내기 | RTF·XLSX 를 라이브러리 없이 직접 생성, 인코딩 정확 | 양호 |

모델 응답은 `json.loads` 에 성공하기만 하면 그대로 화면과 파일로 나갑니다.
README §2 에 일곱 항목짜리 점검표가 있는데 **자동으로 확인되는 항목이 하나도 없습니다.**

## 2. 측정 — 일부러 망가뜨린 응답을 넣어 본 결과

AI 호출부(`_acall_ai`)를 몽키패치해 규격에 어긋난 초안을 돌려주게 했습니다. 전부 통과했습니다.

| 넣은 것 | 기대 | 실제 |
|---|---|---|
| 섹션 2개 (요청은 6개) | 거부 또는 보정 | 그대로 통과 |
| heading "검토 개요" (번호 없음) | 번호 강제 | 번호 없이 문서로 출력 |
| 요청 목록에 없는 `key` | 폐기 | 그대로 통과 |
| 표 제목 39자 | 31자 절단 | 그대로 통과 |
| `columns` 3개인데 행이 2칸·4칸 | 길이 맞춤 | 그대로 통과 |
| "이용객 일 51만 명" (입력에 없는 수치) | 차단 | 그대로 통과 |
| 중간에 잘린 JSON | 폴백 초안 | **빈 문서** (`sections: []`) |

마지막 줄이 특히 아깝습니다 — 바로 아래 `except Exception` 분기는 폴백 초안을 주는데,
폴백이 가장 필요한 파싱 실패 분기만 빈 문서를 내보냅니다.

## 3. 파급 — 검증이 없어서 생기는 것

- **같은 초안에서 RTF 와 XLSX 의 표가 달라진다.**
  행이 `columns` 보다 길면 RTF 는 초과분을 버리고(`report.js:455` 가 `j < n` 으로 고정 순회),
  XLSX 는 헤더 없는 다음 열에 쓴다(`report.js:588` 이 행을 그대로 `map`).
  두 파일을 함께 결재에 올리면 숫자가 어긋난다.
- **채팅으로 초안을 고치면 되돌릴 수 없다.**
  `report.js:1008` 이 `currentDraft.sections = d.sections` 로 통째 교체한다.
  모델이 고친 섹션 하나만 돌려주면 나머지 다섯 장이 조용히 사라진다.
- **폴백과 정상 경로가 다른 문서를 낸다.**
  폴백은 섹션 2개에 `key` 가 `summary`·`priority` 인데 계약은 6개
  (`summary`·`status`·`problem`·`plan`·`effect`·`next`)다. 키가 죽으면 목차 구조가 바뀐다.

## 4. 작업 순서 — 위에서부터 (전부 반영됨)

### ✅ 1) 서버에 `_validate_draft()` 를 넣는다

섹션을 요청한 key 로만 추리고, heading 은 **서버가 가진 정본 문자열로 덮어쓴다.**
표 제목은 31자로 자르고, 각 행을 `columns` 길이에 맞춰 패딩·절단한다.
위 표의 다섯 줄과 RTF·XLSX 불일치가 이 함수 하나로 함께 닫힌다.

```python
def _validate_draft(draft, req_sections):
    HEADINGS = {"summary":"1. 검토 개요", "status":"2. 현황 분석", "problem":"3. 도출된 문제점",
                "plan":"4. 개선 방안", "effect":"5. 기대 효과", "next":"6. 향후 조치 계획"}
    got = {s["key"]: s for s in draft.get("sections", []) if s.get("key") in HEADINGS}
    draft["sections"] = [dict(got[k], heading=HEADINGS[k]) for k in req_sections if k in got]
    for t in draft.get("tables", []):
        t["title"] = str(t.get("title", ""))[:31]
        n = len(t.get("columns", []))
        t["rows"] = [(list(r) + [""] * n)[:n] for r in t.get("rows", [])]
    return draft
```

**위치**: `server/main.py` · `draft_report()` 반환 직전 · 약 12줄

### ✅ 2) 프롬프트에서 죽은 줄을 빼고 금지 문장을 넣는다

`avgMi` 는 `main.py:341` 에서 "항등식이라 −0.0 이 나온다"며 지운 필드인데
`main.py:1483` 이 아직 참조한다. 매 요청 "평균 MI: 미제공"이 실려 나간다.
그 줄을 지우고, README 백로그에만 있는
*"제공된 JSON 에 없는 수치는 어떤 경우에도 쓰지 마십시오"* 를 실제 프롬프트에 올린다.
모델이 채우고 서버가 어차피 덮어쓰는 `generatedAt`·`provider`·`model` 도 예시에서 뺀다.

**위치**: `server/main.py` · 프롬프트 블록 · 3줄 수정 + 1줄 추가

### ✅ 3) 파싱 실패도 폴백 초안으로 돌린다

지금은 `JSONDecodeError` 분기만 빈 문서를 내보낸다. 같은 함수의 다른 분기와 동작을 맞추고
실패 사유를 `disclaimer` 에 함께 적는다.

**위치**: `server/main.py` · except 분기 통합 · 약 4줄

### ✅ 4) 폴백 초안을 6장으로 맞춘다

현황(사분면 분포)·문제점(심야 need 증가)·개선 방안(수단별 배치)·기대 효과(해소 통행량)는
지금 있는 수치만으로 틀을 채울 수 있다. **키가 죽어도 문서의 뼈대는 같아야 한다.**

**위치**: `server/main.py` · `_fallback_report()` · 섹션 4개 추가

### ✅ 5) `stop_reason` 을 확인한다

4096 에서 잘려 파싱이 깨진 적이 있어 8192 로 올렸는데, 표가 길어지면 같은 일이 반복된다.
`stop_reason == "max_tokens"` 를 잘림으로 처리해 폴백이나 재시도로 보낸다.
지금은 잘림이 "JSON 파싱 실패"로만 보인다.

**위치**: `server/main.py` · `_looks_truncated()` — 스트리밍이라 stop_reason 이 올라오지 않아
중괄호가 닫히지 않은 채 끝났는지로 판정한다(잘린 JSON 의 실제 모양).

### ✅ 6) 채팅 초안 교체에 길이 가드를 단다

돌려받은 섹션 수가 원래보다 적으면 반영하지 않는다.
서버 쪽에서는 원본 초안에 없던 숫자가 새로 등장하면 거부하는 검사를 함께 걸 수 있다.

```js
if (d.sections.length < currentDraft.sections.length) return;
```

**위치**: `server/main.py` · `_chat_result()` — 서버에서 막았다. 줄어든 초안은 반영하지 않고
`draftRejected: "sections_shrank"` 를 실어 보낸다. 프론트 `report.js:1008` 의 한 줄 가드는 별도.

## 6. 확인 방법

`tests/test_api.py` 의 **H 구간 9개**가 위 여섯 단계를 잠근다.
AI 호출부(`_acall_ai`)를 대역으로 바꿔 규격 위반 응답을 실제로 넣어 확인한다.

- [x] `sections` 가 정확히 6개이고 heading 이 1~6 번호로 시작한다
      — 처음 이 항목에 [x] 를 칠 때는 사실이 아니었다. `_validate_draft` 는 요청한
      key 로 **거르기만** 했으므로 모델이 5장만 내면 응답도 5장이었고, heading 이
      1~5 로 매끈하게 다시 매겨져 한 장이 빠졌다는 흔적조차 남지 않았다.
      지금은 빠진 장을 눈에 보이는 문구로 채우고 `missingSections` 에 기록한다.
- [x] `tables[].rows` 의 각 행 길이가 `columns` 길이와 같다
- [x] `tables[].title` 이 31자 이내다
- [~] 같은 초안으로 만든 RTF 와 XLSX 의 표 셀 수가 같다
      — 동작은 맞다(서버가 행 길이를 `columns` 에 맞추므로 두 출력이 구조적으로
      같아진다. 프론트 `rtfTable`·`draftToSheets` 를 떼어내 확인함). 다만 **그것을
      지키는 테스트는 없다.** 생성기가 프론트 저장소에 있어 이 스위트에서 닿지 않는다.
- [x] 잘린 JSON 을 넣으면 빈 문서가 아니라 폴백 초안이 나온다
- [x] 채팅이 섹션을 줄여 돌려주면 반영되지 않는다
- [x] 채팅으로 고친 초안도 `_validate_draft` 를 거친다 — 개수만 세던 때는 heading 을
      지우거나 key 를 지어내도 그대로 나갔다

## 7. 프론트에 영향이 가는 지점

**heading 문자열을 이제 서버가 정한다.** 프론트는 그대로 출력하므로 화면·RTF·XLSX 가
함께 바뀐다. 요청한 섹션 순서대로 1 부터 다시 매기므로 일부만 요청해도 번호가 비지 않는다.

표 행 길이를 서버가 맞추면서 **RTF 와 XLSX 의 표가 같아졌다** — 예전에는 초과 칸을
RTF 는 버리고 XLSX 는 헤더 없는 열에 썼다.

`/chat` 응답에 `draftRejected` 필드가 추가됐다(줄어든 초안을 막았을 때만). 프론트가
무시해도 동작에 문제는 없지만, 사용자에게 "일부만 돌아와 반영하지 않았다"고 알려 주면 좋다.
